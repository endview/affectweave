# AffectWeave 1.3：主动对话实施方案

> 实施状态（2026-11-08）：本计划的分析、完整冻结、L2 反馈草稿/确认、回复表达/固定跟进、主动生成宿主、参数/交互及审查演进均已落实到 Go 代码；自动功能默认关闭。历史方案正文保留设计约束，具体已实现/NOT_RUN/延期以 [本版验收记录](VALIDATION_1_6_2026-11-08.md) 为准。两个合成人物真实 DeepSeek 的分析、普通回答与仅生成主动预览已通过；这不替代真人主动 TG 发送及客户端观察。L3 独立业务结果接入/从 L2 补差额仍未交付，明确拒绝模型或保存确认自升 L3。Hytron 生产仍不安装本扩展。


日期：2026-11-08。状态：**待实现、待验收**。当前基线为 AffectWeave 1.1.0-dev.1 / FreeAgent v8.6.0-dev.1；当前宿主只支持固定内容的受控投递，不支持本方案的到期生成。总体顺序见[主计划](AFFECTWEAVE_NEXT_IMPLEMENTATION_PLAN_2026-11-07.md)。

## 1. 产品目标与完成标准

用户明确允许某个人物在某个私聊主动联系后，人物能在合适的时机，结合当前获准上下文判断是否值得开口；值得时生成一句有内容的开场，不值得时保持安静。用户回复后，直接在同一会话继续正常交流。

必须实际跑通：**明确开启 → 合法触发 → 读取当时状态 → 判断说/不说并生成 → 复核 → 实际送达 → 用户回复 → 同一会话接续**。预先写一句话然后定时发送，只能作为已有固定跟进能力，不算本方案完成。

| 场景 | 预期行为 |
| --- | --- |
| 先前明确说过晚些时候想继续一个话题 | 到允许时间重新核查近期交流，仍适合时自然接上；话题已结束则不发 |
| 某个已确认事项到了适合跟进的时间 | 针对该事项提出具体问题；不把计划完成、沉默或猜测当成实际结果 |
| 用户开启“偶尔主动找话题” | 在允许时间与空闲条件满足时，根据明确兴趣或获准近期话题提出一个有内容的问题；可决定不说 |
| 用户正在交谈、执行任务或刚发来新消息 | 优先处理用户输入，取消或延后本次机会，不插入过时开场 |
| 用户没有回复上一次主动开场 | 不继续追问、不换话题绕过限制，不把未回复解释为关系恶化 |

首版面向明确授权的单人私聊，先验收 Telegram。GUI/CLI/Web 共用同一会话和状态，可查询、控制和接续；不把“页面在线”当成 TG 消息已经看见。群聊、跨会话自动选收件人、跨 Core 发起、后台找新闻、操作电脑后主动汇报均不纳入首版人物主动对话。

## 2. 当前能力与真正缺口

| 能力 | 当前实际情况 | 本版增量 |
| --- | --- | --- |
| 人物/关系/情绪/经历 | 已有独立 PG 与上下文；动态分析按主计划 1.2 补齐 | 在触发时读取有效人物与授权范围，形成一次只读评估快照 |
| 普通回复分段 | 显式 single/paragraphs 已有；人物策略选择尚未实现 | E1 先补人物表达；主动开场首版只生成一条文字，正常接续可用已选表达能力 |
| 固定一次性投递 | Core 已有授权、到期、静默、频率、取消、outbox 与回执 | 继续复用，不修改旧候选的固定内容语义 |
| 到期复核 | `delivery.check` 只允许 allow/deny 和有限只读/撤回 Host 调用 | 仍禁止模型、工具和重新生成；主动评估使用单独声明的新能力 |
| 到期生成 | 未实现；当前调度依赖渠道 outbox，不能在其请求内等待模型 | 增加有界唤醒及 Owner 执行入口，生成前后都核对授权与会话版本 |
| 没有新用户输入的身份 | 当前 `ExtensionIdentity` 要求真实 adopted_inputs | 增加明确的扩展触发身份；不伪造用户消息或沿用旧用户输入冒充新请求 |
| 主动消息接续 | 普通渠道消息、会话、reply-to 和结果记录已有 | 将主动 Run、平台消息和后续用户输入正确关联，不另建对话引擎 |

人物参数和情绪交互的复杂算法不是 1.3 的前置；可以使用 1.2 的已确认状态、临时分析与固定基础规则，先验证主动交流是否自然、是否值得额外调用。

## 3. 职责与最小技术选择

| 部分 | 负责的具体内容 |
| --- | --- |
| AffectWeave `internal/affect` | 触发理由、选题、表达约束、说/不说的判断规则；解释人物状态，不决定收件人权限 |
| AffectWeave `internal/storage` | 人物事实、评估来源和结果引用；复用 aw.facts 等记录，不保存可自行派发的队列 |
| AffectWeave `internal/extension` | 在有效调用中提供唤醒建议；到期接受受限回调，借宿主模型生成并返回候选；处理取消与幂等 |
| FreeAgent Core | 已确认授权、目标与身份、到期领取、Run/Attempt、额度、取消、结果冻结和真实交付记录 |
| Telegram 渠道 | 平台身份/消息引用、格式、发送和回执；不判断人物动机，不运行人物模型 |
| Provider | 继续使用 Core 既有配置、Key、协议与用量；AffectWeave 不建立另一套 Provider |
| 前端/CLI | 安装后才提供人物策略入口；以 Core/扩展结果展示状态，使用同一控制确认 |

选择**Core 的有限唤醒 + 既有 Run/Attempt + 扩展的一次评估生成**。扩展自己常驻计时会复制生命周期、恢复和权限；把模型调用塞进 delivery.check 会破坏固定候选复核语义；二者均不采用。

Core 公共字段只表达扩展 ID、不透明资源引用、作用域、授权、触发、截止时间、用量和结果。人物、情绪、亲近程度、兴趣或“是否想念”不成为 Core 的字段或调度条件。不新增消息总线、工作流 DSL、通用 cron 平台、独立调度服务或第二种数据库。

## 4. 开启、授权与持久化边界

**用户已明确要求：必须有“主动对话”总开关，默认关闭，打开后才能主动对话。** 它与“启用 AffectWeave”“自动情绪分析”“允许普通回复/分段”是不同的选择，不能由其中任何一个隐式打开。

总开关放在设置 → 能力 → AffectWeave → 主动对话的第一项。唯一权威值存于 Core 对该扩展 scheduled_generation 的通用授权配置，人物页只展示/操作这个值，不在扩展私库另存一份可能失配的开关。总开关与具体目标规则均有效时才允许执行；必填目标/模型/时段未配置时不能保存为已开启。开启后 Provider 被关闭等情况显示“已授权，当前不可运行”及原因，不能只亮开关却隐瞒不会运行。

| 操作 | 必须行为 |
| --- | --- |
| 首次安装、升级获得新能力 | 默认关闭，不沿用旧固定提醒规则推定允许动态生成 |
| 用户打开 | 展示人物、目标、时间窗、话题范围及额外模型成本并保存具体授权；不立即补发旧机会 |
| 用户关闭 | 立即撤销该扩展全部新的主动机会/模型资格，取消在途评估与尚未派发内容；完成的事实保留 |
| 关闭后重启 Core 或重装扩展 | 仍关闭；不能由旧事件、恢复的备份或缓存重新开启 |
| 重新打开 | 只创建新有效机会，不恢复旧已取消内容或 UNKNOWN 发送 |
| 普通聊天与人物分析 | 不受主动总开关关闭影响；继续按各自已有选择运行 |

用户在同一页面选择人物、具体私聊、允许话题来源、触发方式、时区与时间窗、频率、模型和用量上限，查看影响并确认后开启。模型提出开启、增加频率、改变目标、提高额度或扩大话题来源，同样必须具体确认。GUI、CLI、AI 操作写同一权威开关；关闭不要求再经历一次模型分析。

一次确认可以授权明确范围内的后续判断和发送，不要求每句主动开场再次弹确认。执行中的唤醒记录、调用、候选、已发送状态和去重标记是已授权操作的事实记录；它们不等于批准人物记忆、关系或性格变化。长期状态修改仍生成独立具体预览。

至少同时满足：主动对话总开关打开、扩展已安装/启用、当前会话允许该扩展、人物对目标空间有效、授权者有目标管理权、目标成员与 Bot 身份仍一致、对应规则开启。Core 在创建机会、调用模型、采用结果和平台派发前均核对总开关；只隐藏按钮或仅在创建机会时检查不算实现。Full access、Bot 准入、自动分析开关、允许普通回复均不能代替主动联系授权。

规则绑定扩展资源引用和目标会话。切换默认会话、人物或模型不得把旧机会转给新对象：人物/目标/规则修订改变时旧机会作废；模型采用规则约定的解析方式，在开始评估时冻结实际配置。Provider 不可用时跳过，不自动开启、换 Key 或升级到更贵模型。

首版不授予主动评估工具、命令、文件、网络搜索、嵌入、委派、持久状态写入或再次安排唤醒的权限。需要这些能力的任务由用户在正常会话中另行发起。

## 5. 触发和“不说话”

### 5.1 两种可独立开启的来源

| 模式 | 来源与安排 | 规则 |
| --- | --- | --- |
| 事项跟进 | 用户明确提及稍后继续、明确委托，或已确认未决事项的有效引用 | 正常已采用输入的回调可提出一个机会；必须落在已授权规则内；只是猜测的情绪/意图不能变成新的长期事项 |
| 偶尔开场 | 用户预先开启某人物在指定时间窗主动聊获准兴趣/近期话题 | Core 按固定时间窗创建有限机会，AffectWeave 到时决定具体话题或不发；没有每分钟扫描和随机“模拟真人”活动 |

时间到达只是一次评估机会，不是发送指令。机会来源要有真实 ID 或已确认规则的时间槽 ID；不得从模型自生成的主动消息再递归安排下一次机会。周期模式的下一次机会只来自用户确认的规则。

同一事项/规则/目标只保留一个未结束机会；重复建议合并同一来源，改变具体条件需要新版本。规则删除、人物停用、空间授权撤销、目标迁移均撤销未派发机会。没有渠道或 Owner 运行时不承诺后台唤醒设备。

周期模式使用用户确认的当地评估时刻，初始可建议时间窗内的 10:00、18:00 两个槽，最多使用当天预算允许的槽数。到期时的最早可执行时间是“槽时间、最近用户输入加空闲间隔、冷却结束、静默结束”的最大值；超过该槽期限即跳过。用户任务繁忙时等待现有 Owner 空位或结束期限，不每次轮询都再调用模型。只保留下一有效槽，同一槽 ID 在重启和重复检查中不变。

### 5.2 调用模型前的便宜检查

先检查时间窗、静默、冷却、未回复限制、额度、目标可用性、Owner 是否有派发空间、用户队列与会话状态。任何一项不满足都不调用模型。相同会话已有用户 Run、审批待决或排队输入时不发起主动评估；不因旧任务仅留 UNKNOWN 历史而永久卡住所有未来会话。

初始产品默认值如下，均需实测校准，不能预填验收通过：

| 项目 | 初始值与计算范围 |
| --- | --- |
| 开启状态 | 关闭；用户主动开启才保存规则 |
| 时间 | 用户确认 IANA 时区与时间窗；界面可建议当地 10:00–20:00，不使用服务器时区代替 |
| 空闲条件 | 距目标最近一条真实用户输入至少 4 小时；明确约定的事项跟进按其确认时间处理，仍遵守静默 |
| 评估额度 | 每目标每天至多 2 次；同一 Core 所有这类主动评估合计默认至多 8 次 |
| 发送额度 | 每目标每天至多 1 次主动开场、冷却 6 小时；同一目标多个规则/人物共同计数 |
| 未回复 | 一次已发送或可能已发送的主动开场尚无后续用户输入时，暂停新主动开场 |
| 并发 | 每 Core 至多 1 个主动评估，占用现有可用执行槽；用户任务优先，不增加一套执行池 |
| 有效期 | 一次机会的有效窗口默认 1 小时；不得超出授权时间窗，过期不补发 |

评估次数与发送次数分别计费/计数：“不说话”也用掉一次真实评估额度。到期但尚未派发模型的机会仅占一个待处理位置，不耗模型额度。发送进入可能送达阶段就占用频率与未回复限制；只有明确未派发才能释放相应发送预留。

本专项的“每天”上限按滚动 24 小时核对，时区只影响评估槽、静默与用户看到的日期，不用于清零已消费额度。多规则/人物以及该目标其他扩展主动开场共同核对发送限制，不能用 E1 固定跟进与 E2 动态开场两套计数各发一轮。用户明确创建的一次性提醒和任务结果回传有各自来源，不让扩展自行把主动开场改标成它们以绕过限制。

没有回复是运行上的不打扰条件，不是关系证据。真实授权参与者的新会话输入或显式恢复操作可以解除等待；Bot 自己的消息、生成完成、typing、送达回执和普通页面刷新不能解除。对同一未解决 UNKNOWN 不能靠换规则/来源 ID 重发原内容。

### 5.3 人物判断

便宜检查通过后，AffectWeave 选取少量具体话题依据：已确认兴趣/经历、仍有效的事项、目标会话近期可见消息、自己的近期主动开场事实。人物当前状态按规则投影到当时，但不凭用户沉默增加失落、信任或依赖。

一次模型请求共同决定 `speak` 或 `skip`，并在 speak 时给出最终文字、所选来源和简短原因。不存在先调用一个模型判断、再调用另一个模型写开场的默认双请求。skip 是正常结果，无聊天消息；低置信度、重复话题、没有实质内容或信息不足均可 skip。

结构化响应使用封闭 schema：`decision` 只有 speak/skip；`reason_code` 来自已声明的有限集合；原因摘要最多 256 字符，不保存隐藏推理链。speak 必须有非空正文及 1–3 个来自本次候选列表的 source_refs；skip 正文为空。模型不能返回收件人、权限、revision、调度规则、状态增量或第二次生成请求。未知字段、伪造来源、截断和超限均终止本次生成；不使用自动修复调用补成可发送内容。

开场应与获准来源相关，便于回复，也允许用户不回复。可以表达 AI 角色的想法，不编造真人当下生活、共同经历或外部新鲜事实；不因一次表情认定爱意或因沉默施压。这些是人物内容约束，不扩大成 Core 的人格规则。结构校验只能验证来源引用与形状，不能声称自动证明自然语言全部事实正确。

## 6. 唤醒、身份与一次执行

本节的宿主契约已在配套 FreeAgent v8.7 的 Extension Kit/SUPPLEMENTAL_EXTENSION_EXECUTION 定稿并实现；实现与验收状态分别记录，不以本文充当测试报告。

### 6.1 最小接口增量

- 新能力暂称 `scheduled_generation`。使用该能力的扩展明确声明回调、正数调用/输出上限和所需只读上下文；用户保存规则另行授权。
- 现有 passive_context 继续禁止模型/工具调用。新回调的有限权限由明确能力、当前总开关、规则和执行阶段共同授予，不给普通 context.prepare 或 delivery.check 偷开模型权限；关闭后回到无主动调用的模式。
- 普通有效 `turn.finished` 结果可带一个有界 `wake_hint`，只表达当前作用域内的来源引用、不早于/不晚于时间和不透明事项引用。Core 补全身份与目标，不接受模型提供新 Bot、收件人、Core ID、SQL 或路径。周期规则由 Core 自行生成时间槽机会，不依赖扩展常驻。
- 到期调用暂称 `wake.evaluate`：收到新 invocation、扩展触发身份、规则版本、实际时间、冻结上下文和额度；允许一次无工具 `model.generate` 及 activity.report。返回受限的 speak/skip 结果，不能自行发送、写状态或创建下一机会。
- Core 将获准的 speak 结果经既有准备、冻结、outbox 交付；不在 wake 回调里开放任意 delivery.propose，避免一次机会同时走两条发送路径。规则读取/暂停/取消继续走现有控制和状态视图，不建立任意 RPC 转发。
- `delivery.check` 保持固定候选复核的现有权限和响应。E1 固定跟进与 E2 动态主动对话是两个明确模式；不能让旧规则静默获得新模型调用能力。

### 6.2 身份不能伪造

Core 为唤醒绑定：授权操作及规则修订、扩展/资源、Core/空间/会话、当前接收者与渠道授权版本、来源事件/时间槽、唯一机会 ID 和新 Run ID。授权操作者、业务参与者、触发者三个含义分开：触发者明确为扩展规则；读取某参与者的人物状态不等于冒称该参与者刚发了一条消息。

当前 `extensionIdentity` 从真实用户消息读取 adopted_inputs，不能直接拿来构造主动执行。新增的通用触发联合类型必须允许“无新用户输入”的明确分支；真实旧输入只能作为 source_refs，不复制为本轮 adopted_inputs，不给旧输入分配新采用时间。现有人物模型提案的来源权限不能因这条分支放宽。

主动评估不调用 `Store.Adopt` 增加用户输入或推进关系。读取已确认状态的只读衰减投影，结果与片段记录到原机会对应的事实/执行快照。后续真实用户回复才进入正常 Adopt/分析路径。

### 6.3 派发与交付步骤

1. Core 在现有 PG meta 中持久化有限唤醒信息，业务事项仍在扩展库。按唯一机会键进行短事务领取，并关联一个现有 Run；同一时间槽不能创建第二个 Run。网络调用期间不持行锁。
2. 通过 Owner 现有任务入口运行，明确标记扩展触发和无工具权限。到期查询只安排执行，不在 TG outbox 轮询/回执 HTTP 请求内等待模型，以免拖住普通消息交付。
3. 开始时再次检查授权、空闲和额度，冻结实际模型、人物/规则/上下文版本及目标用户输入水位，记录真实 Model Attempt。开启普通“自动输入分析”不是本次唤醒再加一次分析的理由。
4. AffectWeave 返回 skip 或一条开场文字。skip 正常结束为未发送；有效 speak 保存生成结果及来源后，再检查用户输入水位、人物/规则版本、授权、期限与发送额度。
5. Core 通过同一提交边界关联生成结果与待交付组，崩溃恢复不得出现已送达但丢失组关联后再建一组。沿用现有整组冻结、按序发送、逐项 receipt。首版开场是一条文字，平台长度分片仍按实际逐片记录。
6. 生成记录与发送记录独立展示。发送成功才进入目标空间的已交付上下文；skip、失败、取消以及未确认发送内容不混入渠道公开历史。之后的真实用户回复使用同一会话正常处理。

Owner 只在存在已启用规则/待处理机会时挂接必要的有限到期检查；停用后解除，没有配置时零新增周期扫描/进程/模型请求。TG 只需要持续正常收发。没有活动 Owner 时不唤醒电脑，恢复在线后过期机会结束为错过；同一周期最多保留下一次有效机会，不积压离线期间的开场。

## 7. 上下文、模型与预算

| 输入 | 范围 |
| --- | --- |
| 人物 | 授权资源的当前身份/边界、已确认状态和受限经历；保持确定的版本引用 |
| 近期交流 | 同一目标会话最多 8 个完整轮次，受总预算收紧；只包括该空间可见的用户输入和已确认交付的回答 |
| 话题 | 最多 3 个合法候选引用与短摘要；未确认草稿不作为长期事实 |
| 运行事实 | 当前时间/时区、空闲时长、上次主动联系的真实状态、规则可用额度；不提供 Key、系统日志或其他私聊 |

全局/工作区 Memory、Skill 和其他会话资料不会因主动模式自动获得权限。即使是本机 Owner 的私聊，首版主动来源仍受用户确认的具体范围约束。需要拓宽来源时重新确认。

初值：每机会最多 1 个真实 Provider 请求；输入最多 4096 tokens 的估算预算，输出最多 1024 tokens；总评估期限默认 30 秒，可配置 5–120 秒且受宿主截止时间限制。正文默认至多 600 个 Unicode 字符，超限/截断拒绝，不暗中裁掉内容再发送。与主计划普通输入分析的 8 秒预算分别记录，二者不是同一回调。

实现时同步调整宿主与扩展的阶段期限：wake.evaluate 获得明确截止时间，模型须在剩余时间内结束，并为结果保存/返回留出余量；现有固定 20 秒 stdio 期限和 manifest 的短回调期限不能默默截断 30 秒配置。普通状态读取、活动回报和 delivery.check 保持各自短期限，不能为了主动生成统一延长所有回调。

模型默认按规则在开始时解析会话的明确模型并冻结；选择 auto 而无法无额外评估解析实际模型时跳过并提示设置，不偷偷触发额外路由调用。思考字段只使用 Provider 已声明的能力，计算输出/思考费用依实际 usage，不能把思考 tokens 当作免费。

输出额度派发前预留，UNKNOWN 或缺 usage 时按保留额度处理；所有主动规则汇总实际 Attempt，关闭/重开、改规则 ID、切人物或重启不重置当天已经消费的额度。没有第二份额度数据库。补充模型请求默认关闭自动重试和替代；失败或结构不合法就 skip/error，不调用“修 JSON”模型。

这些是调用和 token 上限，不是未经计价的金额保证。Provider 的输出/思考上限按已声明协议处理；无法兑现本次调用上限的模型不能作为主动生成模型。实际 usage 缺失时展示估算或未知，不填写虚构费用。

## 8. 抢占、恢复与不确定结果

| 情况 | 必须行为 |
| --- | --- |
| 用户输入在领取前到达 | 更新输入水位，按规则取消旧机会；用户任务优先 |
| 用户输入在生成中到达 | 取消主动 Run，停止采用结果；普通消息进入正常队列/引导，不引导这个主动 Run继续说话 |
| 生成完成但尚未开始平台派发 | 再查输入、版本和授权；变化则不发，不自动重新生成 |
| 平台派发后收到用户输入/停止 | 停未发尾段；已派发可能送达，按真实回执记录，不能承诺撤回 |
| 领取后、Provider 尚未派发就崩溃 | 在能证明未派发且授权/期限仍有效时恢复原机会/原 Run；不增加第二个 Run |
| Provider 已派发但结果未落定 | 保留调用 UNKNOWN 与额度，不自动再问模型；本次不产生外部发送 |
| 扩展已保存候选但 Core 未收到/未保存响应 | 保留原机会的不确定调用事实，本次不发；不重新进入回调取得新结果。仅 Core 已持久接受的原候选可以续接交付 |
| 生成结果已持久化、入队前崩溃 | 从同一冻结结果与关联键核对/续接；不重新生成 |
| 平台明确拒绝/429 | 按现有确定性结果和有效期处理；重试不改变原文、目标和组身份 |
| 平台结果 UNKNOWN | 原内容不重发；暂停原组尾段，保留未回复限制和实际费用/证据 |
| 时钟变化、DST、修改时区 | 截止时间保存 UTC，时间槽绑定规则修订和当地日期；重复小时不重复触发，缺失窗口跳过，不靠调整时间清额度 |
| 更新、卸载或人物删除 | 撤销未派发机会、旧 invocation 与新的调用资格；已生成/交付事实仍保留，恢复安装也不重放旧机会 |

恢复查询始终针对原执行与回执。主动 Run 在取消、失败或模型 UNKNOWN 后必须释放执行槽；保留其不确定记录，不把普通新输入卡在这个无工具的主动任务之后。内部失败不能发送“我在等你”等补偿消息，也不通过新随机 key 或新规则重做同一副作用。不能解决的恢复结果明确 UNKNOWN。

## 9. 用户回复与连续性

主动开场绑定原会话与主题来源，平台消息 ID 映射回实际 Run/交付部分。用户 reply-to 命中该消息时可建立明确反馈关系；没有引用时，当前会话普通消息正常回复，不擅自认定它评价了上次主动开场。

用户输入后本次主动周期结束，回复由正常 Core 对话执行，保留其原有队列/引导、工具权限、压缩和人物选择。不创建隐藏的第二个会话、不切换 TG 默认会话、不自动连续发送多个轮次。GUI/CLI attach 打开相同会话时能看到同一已交付内容和主动来源标识。

下一次自动机会仅按已确认规则重新安排；当有未回复开场时暂停。新输入解决了旧事项，旧事项机会取消；不能为了保留计划而强行问一个已经回答的问题。

未回复、emoji 或送达状态不能直接增加/降低信任与关系。需要长期保留的反馈仍走主计划的来源、草稿、预览和具体确认。

## 10. 存储与双库一致性

- Core：复用现有配置/控制记录保存授权，fa.meta 保存有限机会描述/领取/取消/Run 关联；Run/Attempt 保存实际执行和用量；消息/outbox 保存生成与真实交付。不新增 WakeJob、ConversationAgent、Checkpoint 或跨库事务框架。
- AffectWeave：继续 aw.roles/states/memories；主动评估快照、候选理由与 Core 结果引用优先用 aw.facts 的受限类型与稳定来源键。不是用户输入的事实不插入 aw.inputs；不为主动模式复制一份聊天历史。
- Core 是执行/发送权威，扩展是人物业务权威。扩展镜像写失败时可通过既有原事实同步补读；只补事实，不补执行。确认扩展评估结果落定后才能交给 Core 作为可发送候选，任何跨边界不确定性均不能通过重跑模型解决。
- Core 接受并保存过的候选才能续接交付；如果只有扩展库保存而 Host 回调结果丢失，按第 8 节结束本次机会，不复用 state.result 冒充模型结果查询。现行 state.result 专属已确认状态操作，主动模型调用仍以原 Attempt 和冻结结果为准。
- 每规则/目标最多一个未结束的周期机会；每事项只保留一个待机会。机会数量与数据大小沿用明确有限上限；终态记录按既有维护策略保留，去重和额度所需记录不得先清掉。
- 备份覆盖规则、机会、Run/Attempt、outbox、扩展快照和同步位置。恢复到新目标默认不自动派发备份中未结束的主动机会，先核对目标和现存平台事实；旧实例与恢复实例不能同时领取同一 Bot。

## 11. 产品设置与开发位置

| 入口 | 内容 |
| --- | --- |
| AffectWeave → 主动对话 | 人物、话题来源、事项跟进/偶尔开场、频率建议、为何想说/为何跳过；安装后才出现 |
| 主动对话总开关 | 默认关闭；直接对应 Core 对该扩展的总授权，展示有效/未配置/已暂停原因；所有触发路径共用 |
| Core 投递授权 | 复用并增补通用允许生成/发送、目标、时间窗、模型额度；人物页跳转同一配置，不保存第二份 |
| 对话输入区 | 本会话人物与本轮能力；只读标识当前是否允许主动联系，不塞全局规则表单 |
| 主动记录 | 原因摘要、下次机会、实际调用/费用、生成/跳过/取消/送达/UNKNOWN；默认折叠 |
| 暂停/恢复 | 显式用户操作，经同一控制入口作用到指定规则/目标；暂停先撤销未派发机会，历史保留 |
| 预览一次 | 明确“只生成不发送”，仍消耗显示的模型额度；预览结果不可被自动升级成发送 |

聊天提出设置修改、GUI 卡片与 CLI 提示都映射同一控制操作；目标、内容范围、额度或规则变化重新确认。自然语言意图不绕过持久确认。用户的普通新消息立即取消旧机会，但不隐式修改长期规则。命令名在实现时基于既有入口确定，不在本方案虚构已可执行命令。

FreeAgent 预计改动范围：现有 extension manifest/调用权限、通用触发身份、TaskService/Owner 派发、调用预算、delivery 授权与 outbox、状态/设置页；各处只补本次通用缺口。AffectWeave 预计改动范围：双向 RPC、主动策略纯函数、片段与来源选择、评估事实、到期响应。每个 Core 增量须列“必要性、无扩展成本、既有行为回归”，禁止追加人物专用调度分支。

## 12. 实施拆分与验收

| 阶段 | 产物 | 退出条件 |
| --- | --- | --- |
| E2a：离线决策 | 触发/空闲/重复/未回复策略、一次 speak/skip 提示、来源快照、预览入口 | 受控模型与真实 PG；无发送时能复现跳过与生成，关闭零额外请求 |
| E2b：宿主唤醒 | 显式能力、无新用户消息的身份、有界派发、预算和取消、原 Run 恢复 | 非人物合成扩展也能使用；无模型/权限/目标冒用、重复 Run 或 outbox 阻塞 |
| E2c：真实组合 | Core + AffectWeave + 独立渠道进程，语义冻结到实际回执与用户回复 | 受控平台端到端，包含迟到输入、分片、UNKNOWN、停用/卸载、GUI/CLI接续 |
| E2d：实际使用 | 两个合成人物的真实 Provider、获授权测试私聊、多轮自然接续 | 汇报所有调用/跳过/发送和观察结果，完成 Windows/Debian 12 最终包及配套备份恢复 |

至少覆盖：

- 约定话题、未决事项、自由兴趣、无有效话题、事项已解决、用户正在忙、上次未回复；固定样例既有 speak 又有 skip，不以“永远不发”通过。
- 不同人物面对相同事件的表达差异；不编造当下生活、不强行安慰、不每次重复问候。真实模型采用固定测试集记录全部结果、首次开场延迟和额外用量，不只展示最佳样本。
- 默认关闭、只开人物/分析但未开主动、开启后执行、生成中关闭、发送前关闭、派发后关闭、关闭后重启、重新开启：均通过同一开关验收；前端状态必须等 Core 确认，保存失败不能显示为已生效。
- 跨空间/收件人伪造、旧 grant、换人物/默认会话、超额度、缺 usage、重启/重开规则、多个规则共同消耗、用户插话与发送抢占。
- 每个领取/模型派发/结果保存/冻结/发送/回执边界注入故障；两次到期查询只生成一个机会/Run；模型 UNKNOWN 不自动再生成，发送 UNKNOWN 不重投。
- 无渠道、停用扩展、未选择人物、无已启用 Provider、Owner 离线后重开、DST/时钟跳变；未启用时与当前轻内核的进程/查询/模型成本对比。
- 用户端真实观察：开场已收到、回复能接上、暂停有效。没有收件人授权或客户端观察条件记 NOT_RUN；不自动向生产私聊发送验收消息。

指标初值：纯规则 p95 < 5ms；本地取消收到后 p95 < 1 秒停止采用主动结果；模型阶段受配置期限限制；等待一个慢模型期间普通渠道回执/入站/typing 不被阻塞。记录样本、环境和实际数值，不把本方案当作测试结果。

E2a–E2d 完成才能称“主动对话可用”。固定提醒通过、候选成功保存、文本成功生成、TG 已发送以及用户自然接续分别验收。没有重装 Hytron、启用规则或真人发送的当前授权时，交付包与模拟验收继续完成，部署/启用按用户当时选择执行。
